How I work

The same four steps whether it's a statewide website or a weekend product.

  1. Understand the people

    Talk with the users and stakeholders first, so I'm solving the real problem rather than the assumed one.

  2. Evaluate before building

    Review the existing system, weigh the options, and recommend the approach that's feasible and maintainable.

  3. Build it to last

    Write clean, object-oriented code with reusable components, and test it against a written plan.

  4. Ship and improve

    Release through automated pipelines, watch how it performs, and keep tuning after launch.
